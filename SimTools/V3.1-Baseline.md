# V3.1 Frozen Baseline

The naming overhaul (Phase 1 + the six-layer semantic stack) moved name generation onto its own
deterministic RNG stream, isolated from `GD.Rand`. That stream separation shifted the global RNG
sequence like a seed change, so the V3 reference numbers no longer reproduce byte-for-byte. This
document freezes the **V3.1** reference decade that future calibration work measures against.

## Provenance

- **Commit:** `179809beb140d59a71e6b3a0f937e5356e849f51` (branch `naming-generation-overhaul`)
- **Naming engine:** six-layer stack live (`NameGenerator ready: 2550 words, 64 symbols, 32 genre profiles`)
- **Seed:** 1001 (single seed — genres are no longer being tuned, so cross-seed genre noise is not
  being characterized here; add 1002/1003 if a future change reopens genre tuning)
- **Wall time:** ~32 min (full-fidelity; the artist-population-lifecycle + genre-market-v2 systems active)

### Reproduction command

```
<Godot-console.exe> --headless --path . SimTools/ChartAuditRunner.tscn -- \
  --weeks=522 --seed=1001 --enable-genre-market-v2 --enable-artist-population-lifecycle \
  --calibration --run=v31-1001
```

The two `--enable-*` flags are **load-bearing** — without them the sim runs a much smaller static
population (~2× fewer records, ~7 min) and the metrics are NOT comparable. Always include them.

## Why the naming overhaul is safe for the sim

Naming draws from a dedicated `DeterministicRandom`, never `GD.Rand`. Verified empirically: at the
pre-work commit `40bf0ae` and at HEAD, the name-free sim fingerprints (`calibration-decisions`,
`market-revenue`, `concentration`, `tier-volume`) are **byte-identical** — and stayed identical even
though the two builds loaded different naming data (50 vs 64 grammar symbols). The naming layer does
not perturb sim/chart/economy output; the V3→V3.1 shift is entirely the one-time stream separation.
